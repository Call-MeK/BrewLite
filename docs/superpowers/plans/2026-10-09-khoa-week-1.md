# Anh Khoa — Week 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Anh Khoa điều phối nhóm và tích hợp Menu lấy dữ liệu thật từ API Product, với hướng dẫn chạy thống nhất và bản demo tuần 1.

**Architecture:** Giữ cấu trúc `frontend/` Next.js và `backend/` NestJS hiện có. Tấn Nin phụ trách Product backend, Hoàng An phụ trách Menu frontend; anh Khoa thống nhất cấu hình, review và tích hợp. Prisma setup được phối hợp giữa hai thành viên backend và Tech Lead, không tự thay đổi ownership.

**Tech Stack:** Next.js, React, TypeScript, Tailwind CSS, NestJS, PostgreSQL, Prisma, npm, GitHub.

**Spec:** `docs/superpowers/specs/file.md`, mục 6, 10, 11 và 12.

## Global Constraints

- TV1: Anh Khoa — Leader / Scrum Master / Tech Lead / Integration.
- TV2: Tấn Nin — Product, Order, Inventory; TV3: Quốc Anh — Auth, Payment, Voucher, Loyalty.
- TV4: Hoàng An — Menu, Product Detail, Order History; TV5: Thị Thúy — Cart, Checkout, Payment Confirmation; TV6: Đức Phúc — BA, QA, Test Cases, UML / Documentation.
- GET /products public, trả `{data:[{id,name,basePrice,imageUrl,stock,isAvailable}]}`; ID UUID, giá integer VND; `isAvailable = stock > 0`, không pagination trong MVP.
- Node.js 24 LTS theo README; dùng npm và lockfile riêng cho frontend/backend.
- Theo spec, dùng `NEXT_PUBLIC_API_BASE_URL` cho public API origin; database URL và secret chỉ nằm ở backend.
- Không ghi đè env local; không commit `.env` hay `.env.local`; chỉ chia sẻ `.env.example`.
- Dùng feature branch và PR review; lịch tuần là đề xuất, giữ khoảng 20% thời gian cho tích hợp/sửa lỗi.
- CI và Docker Compose đủ ba dịch vụ thuộc tuần 4; tuần 1 chỉ cần PostgreSQL dev chạy được theo cách nhóm thống nhất.

## Review Focus

- Clone/cài đặt mới: hướng dẫn phải chạy được với lockfiles và env mẫu; kiểm tra ở việc 02 và 07.
- Tên biến API khác nhau giữa spec và repo: client phải dùng cùng tên với env mẫu/README; kiểm tra ở việc 03 và 06.
- API không có sản phẩm: Menu hiện trạng thái trống; kiểm tra ở việc 06.
- Backend ngừng chạy hoặc mạng chậm: Menu hiện lỗi hoặc loading, không đứng ở màn hình trắng; kiểm tra ở việc 06.
- Sản phẩm stock = 0: API trả isAvailable = false và Menu biểu thị hết hàng; kiểm tra ở việc 05 và 06.

## Hiện trạng đã đọc

- Có scaffold frontend/backend, npm lockfiles, env mẫu và README root; không cần tạo lại.
- Backend hiện chỉ có GET / trả `Hello World!`; chưa có Prisma hay ProductsModule.
- Frontend hiện là trang giới thiệu; chưa có Menu hay API client.
- README ghi nhánh chính `main`; nhánh checkout khi lập kế hoạch là `develop`. Cần xác định nhánh đích PR với nhóm trước khi sửa hướng dẫn, không tự đổi tên nhánh.
- Frontend env mẫu và README hiện dùng `NEXT_PUBLIC_API_URL`, khác tên trong spec.
- Chưa chạy build, lint, test hay dev server khi lập kế hoạch.

## File Structure

- Anh Khoa cập nhật khi thực hiện: `README.md`, `frontend/.env.example`, `backend/.env.example`; `backend/src/main.ts` chỉ khi cần điều chỉnh CORS để tích hợp.
- Tấn Nin phụ trách deliverable dự kiến: `backend/prisma/schema.prisma`, migrations/seed, hạ tầng Prisma dùng chung và `backend/src/products/`; thống nhất tên file trước khi làm để tránh hai backend tạo trùng.
- Hoàng An phụ trách: `frontend/src/app/page.tsx` và các file Menu/API client thực sự cần thiết; dùng đúng biến môi trường đã thống nhất.
- Bảng phân công trên GitHub và link Figma/UML là đầu ra phối hợp; không gửi thông báo, tạo Issue/PR hay sửa tài liệu của người khác trong bước lập kế hoạch này.

## Task 02: Xác nhận cách chạy dự án hiện tại — 1 giờ

**Files:** Đọc/cập nhật `README.md`; đối chiếu hai `package.json`, lockfiles và env mẫu.
**Interfaces:** Dùng scripts có sẵn, không thêm script/wrapper nếu chưa cần.

- [ ] Kiểm tra `node --version` đáp ứng Node 24 LTS và `npm --version`.
- [ ] Chạy `npm --prefix frontend ci` và `npm --prefix backend ci`.
- [ ] Chỉ copy env mẫu nếu env local chưa tồn tại.
- [ ] Chạy `npm --prefix frontend run dev` và `npm --prefix backend run start:dev` ở hai terminal.
- [ ] Kiểm tra frontend localhost:3000 trả HTTP 200, backend localhost:3001 trả `Hello World!`; ghi hướng dẫn xử lý port bị chiếm nếu gặp.

**Hoàn thành khi:** Hai ứng dụng chạy theo README; hướng dẫn nhánh Git khớp nhánh đích nhóm vừa xác định ở Task 01.

## Task 03: Thống nhất cấu hình và Product API contract — 1 giờ

**Files:** `README.md`, `frontend/.env.example`, `backend/.env.example`; đối chiếu `backend/src/main.ts`.
**Interfaces:** Menu gọi GET /products trên origin trong `NEXT_PUBLIC_API_BASE_URL`; backend trả response theo mục 6 spec.

- [ ] Thống nhất frontend dev origin localhost:3000 và backend origin localhost:3001.
- [ ] Đổi tên biến trong env mẫu và README từ `NEXT_PUBLIC_API_URL` sang `NEXT_PUBLIC_API_BASE_URL`; hướng dẫn mỗi thành viên cập nhật env local và khởi động lại frontend.
- [ ] Ghi rõ GET /products trả wrapper `data`, các field, giá integer VND, không yêu cầu JWT và `isAvailable = stock > 0`.
- [ ] Đối chiếu CORS hiện có với origin frontend; chỉ sửa nếu cấu hình thực tế đòi hỏi, không mở wildcard để chữa lỗi.
- [ ] Xác nhận Tấn Nin và Hoàng An dùng cùng contract; frontend chỉ giữ public API origin, không có database URL/secret.

**Hoàn thành khi:** Env mẫu, README và consumer frontend dự kiến thống nhất tên biến/response; không có secret trong cấu hình public.

## Task 04: Phối hợp bàn giao PostgreSQL/Prisma — 1,5 giờ

**Files:** Review file Prisma/migration/seed của backend owner và cập nhật hướng dẫn DB ở `README.md`, `backend/.env.example` nếu cần.
**Interfaces:** Backend owner bàn giao lệnh migration/seed đúng với package scripts đã thêm; ProductsModule dùng Prisma chung.

- [ ] Thống nhất một PostgreSQL dev database và thông tin mẫu trong DATABASE_URL, không dùng dữ liệu thật hay DB dùng chung cho kiểm thử phá dữ liệu.
- [ ] Review schema Product với Tấn Nin: UUID, name, imageUrl, basePrice integer VND, stock không âm, version mặc định 0; isAvailable computed.
- [ ] Review vị trí PrismaService dùng chung với hai thành viên backend để tránh mỗi module tự tạo kết nối riêng.
- [ ] Trên DB dev mới, chạy đúng lệnh migration/seed do backend owner bàn giao; xác nhận có sản phẩm và một sản phẩm hết hàng cho smoke test.
- [ ] Ghi chính xác lệnh và cách cấu hình DB vào README; không reset database đang có dữ liệu để kiểm tra.

**Hoàn thành khi:** Backend kết nối DB; người khác có thể làm theo README để tạo schema và dữ liệu dev. Phần triển khai Product vẫn do Tấn Nin phụ trách.

## Task 05: Review và tích hợp Product API — 1 giờ

**Interfaces:** GET /products trả `{data: ProductSummary[]}` đúng Task 03.

- [ ] Review response thực tế: đủ field, đúng kiểu, không passwordHash/secret, không yêu cầu đăng nhập.
- [ ] Kiểm tra GET /products với dữ liệu seed; kiểm tra stock = 0 trả isAvailable = false và catalog trống trả `{data:[]}` trên DB dev phù hợp.
- [ ] Chạy `npm --prefix backend run lint`, `npm --prefix backend run build`, `npm --prefix backend test` và `npm --prefix backend run test:e2e`; yêu cầu test Product trong PR backend owner.
- [ ] Chỉ tích hợp PR khi review và các kiểm tra liên quan đạt; lưu vướng mắc rõ ràng nếu chưa đạt.

**Hoàn thành khi:** API đọc dữ liệu thật từ PostgreSQL và Hoàng An dùng được response đã thống nhất.
